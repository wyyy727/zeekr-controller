| 项 | 说明 | 状态 |

**判定方法**（不必重新登录）：登录成功后令牌落盘 `server/data/session.json`，
之后"哪个路径对 / 哪个字段名对 / 哪组密钥对"都能用**换一个候选重发同一条 GET** 问网关，
零短信成本。

- 返回 `079025 Signature authentication failed` → 签名串构造或**密钥**有误
- 返回 `079025 Decrypt X-VIN failed` → **同一个错误码**，但问题在 X-VIN 加密（见第二节）
- 返回 `079001 接口未被授权` → 签名已通过，问题在令牌代际或账号权限
- 返回 `000000` + 数据 → ✅ 通过

> ⚠️ `079025` 是**复用错误码**。日志已按 `msg` 分流；只打码不打 msg 会把排查方向带偏
> （本项目踩过：一直误判成签名问题，实际是 X-VIN 密钥不对）。

### 车辆位置（2026-10-19 落地，地址与地图需另配 key）

坐标来源：`basicVehicleStatus.position.latitude/longitude`，**字符串小数、6 位精度**。
后端走 `_raw_float` 而**不是** `as_float` —— 后者保留 2 位小数，等于 1.1 km 误差。

**三条容易踩的坑**：

| 事实 | 含义 |
|---|---|
| 15 条真车快照里只有 **3 个位置点**，同位置连续 10 条坐标完全一致 | **车静止时网关不更新坐标**，这是「最后一次上报的位置」，不是实时定位。界面必须显示 `lastUpdateTs` |
| 实测 11:27 抓取时，车上报时间是 **10:48**（滞后 39 分钟） | 不显示时间就会被当成"车现在就在这" |
| `positionTrusted` **15/15 全是 False**，从没出现过 True | 语义未确认，**不能拿它做"定位不准"的提示**，否则会一直误报 |

**外部依赖**：地址与地图由腾讯位置服务提供（合规上只能用腾讯/高德/百度/天地图，
**Apple Maps 属禁止清单，iOS 端也不能用 MapKit**）。需要 `TENCENT_MAP_KEY`，
并开通「逆地理编码」与「静态图」两个 WebService API。未配置时降级为：
只显示上报时间，不请求第三方、不显示地图。

> **经纬度不在界面上展示**（2026-10-21 起，网页与 iOS 同步）：`31.2035, 121.5858`
> 这类数字对人没有信息量，判断"车在哪"只能靠地址与地图；把精确坐标摆在屏幕上
> 属于多余暴露。坐标仍由 `lat`/`lng` 提供给地图，只是不渲染成文字。

**key 只在服务端**：前端请求 `/api/vehicle/location/map.png`，由后端带 key 代取图片。
腾讯静态图常规用法是前端拼 URL，那等于把 key 公开在 HTML 里，本项目不这么做。

⚠️ **隐私边界**：这是全项目唯一把「车在哪」发给第三方的路径，用户已明确同意。
日志里不打印坐标与地址；坐标也不走 query 参数（uvicorn access log 会记录完整 URL）。

**减少外发的手段：坐标不变就不请求**。地址写入 `geocode_cache` 表、地图图片落到
`server/data/mapcache/`（都在 `.gitignore` 覆盖范围内），缓存键取坐标的 5 位小数
（≈1 米）。车停几天不动 ⇒ 只查一次腾讯；接口返回的 `addressFromCache=true`
就表示这次没有外发。车换了位置 ⇒ 新坐标没有缓存，自然重新请求。

### 行程与能耗：**已打通**（2026-10-20，推翻 10-19 的"拿不到"结论）

官方 App「行程统计」页的数据来自 `journey-statistics-service` 的 **H5 命名空间**，
用项目现成的 GW3 签名可直接调用（**不需要** 那套 `X-API-SIGNATURE-VERSION: Third`）。

| 用途 | 路径 | 请求体 |
|---|---|---|
| 汇总 + 逐日（**主力**） | `/h5/getDailyStatisticsInfo` | `{vin, start: ms, end: ms}` |
| 月度报告（60 天以前） | `/h5/getMonthlyStatisticsInfo` | `{vin, yearMonth:"2026-09"}` |
| 可选月份 / 总里程 | `/h5/mileageBaseInfo` | `{vin}` |
| 协议确认（幂等） | `/phone/protocolConfirm` | `{}` |

**口径（已用真车数据交叉验算）**
- **总电耗** = `electricityConsumed` = Σ(`dynamicEcY`) + Σ(`staticEcY`)
- **动态电耗** = `dynamicEc`；**平均动态百公里电耗** = `dynamicAvgEc`
- 逐日电耗（柱状图）也必须是 `dynamicEcY[i] + staticEcY[i]`，**`ecy` 恒 0，不能用**
- 总里程 = `totalMileage` = Σ(`dailyMileageY`)；X 轴**只含有数据的日期**，按 X 对齐而不是按下标

**三道限制（都踩过）**
| 现象 | 原因 | 处理 |
|---|---|---|
| `A008` | 窗口超过 **31 个自然日** | 前端夹到 31；窗口按自然日算（`今天-(N-1)` 的 00:00 起） |
| `A010 只允许查询60天内数据` | 日统计接口的回溯上限 | 更早的月份改走 `getMonthlyStatisticsInfo` |
| `A007` | 月报**不允许查当月** | 当月一律用 `getDailyStatisticsInfo` |

**为什么 10-19 判断"拿不到"**（方法论教训，别再犯）
当时按 `phone` 命名空间 + 名词词根（report / statistics / energy / month…）枚举了 136 条路径，
全 `00A01`，据此得出"接口不存在"。真实原因是**双错叠加**：
命名空间是 `h5` 不是 `phone`，方法名是 `getXxxInfo` 不是名词。
⇒ 正确做法是**先找到前端代码读它调什么**（H5 路由 `/minapp/wap/trip/home` →
`snc-static.zeekrlife.com` 的页面 → webpack chunk），而不是猜路径问网关。

⇒ 跑一次测试或一次模拟模式就写一批。**已修**（mock 不落库 + 测试用临时库）。

⇒ 结论修正：**行程接口至今没有成功返回过任何真实数据。** 10-19 拿真实会话再查，
无论怎么传参都是 `total=0, data=null`。

### 充电流水：**已打通**（2026-10-21）

官方 App「充电记录」页的数据源，一条请求就能拿到约两年的全部流水。

| 项目 | 结论 |
|---|---|
| 路径 | `POST /ms-charge-manage/api/v2.0/charge/log/queryGroupMouth` |
| 请求体 | `{"startTimeStart": null, "chargeType": ""}`（`chargeType` 传 `AC`/`DC` 实测可过滤） |
| 必带头 | `X-TENANT-ID: ZEEKR` + `X-VEHICLE-BRAND: ZEEKR`，**缺一个就 `079001`** |
| 鉴权 | GW3 签名 + `gw3_token`，`X-VIN` 必须是**加密后的**（明文 `079025 Decrypt X-VIN failed.`） |
| 返回 | `[{year, monthList: [{yearMonth, count, sumPower, records: [...]}]}]` |
| 逐笔字段 | `eventId` / `startTime`(ms) / `endTime`(ms) / `chargedTime`(**分钟**) / `power`(度) / `chargeTypeName`(直流/交流) |
| **没有的字段** | 金额、单价、站点名 |
| 实测 | **68 笔 / 3468.5 kWh / 10 个月（2026-01 ~ 2026-10）**，与 App 逐月对得上（10 月 4 笔 234.2 度） |

**口径**：充入电量 = Σ`power`；次数含电量缺失的记录（次数与电量是两个维度）；
平均功率 = 电量 ÷ (时长/60)。落库表 `charge_sessions`，**不存 VIN**。

**金额为什么拿不到**：车端报文里没有任何 `fee/cost/amount/price` 字段，
站点也不在充电记录里；官方「补能订单」金额页在浩汉网关后、要浩汉账号态
⇒ 不可自动化。金额只剩**截图识别 / 手工 / 估算**三条路（已全部实现）。

**配对口径待真机验证**（⬜）：官方订单号在支付侧、充电流水里没有，
所以只能靠「电量 ±5% + 起点 ±10 分钟」对齐。**需要拿一张真实订单截图**
（App「补能订单」页）跑一次 OCR，逐笔核对：

- [ ] 识别出的金额与订单页**实付**金额一致（不是服务费原价、不是总额）
- [ ] 强匹配能自动绑上，且绑的是同一次充电（对照 App 里的起止时间）
- [ ] 同一天充两次时**不会**被自动绑定，而是进「待确认」

### 为什么官方 App 自己不展示按次行程（2026-10-19 从 APK 结构查证）

- 官方行程页是**小程序**：dex 里有一条页面路由 **`/minapp/wap/trip/home`**，
  对应的代码不在 dex 里，而在 `assets/hybrid/*.zip`（18 个离线包，**全部加密**，
  Python `zipfile` 一律 `BadZipFile`）。
- dex 里能读到的是 **SDK 的壳**：`com/geely/snc/location/base/mode/journallog/`
  下有 `JournalLogListRequestBean`、`JournalLogListResultBean`、`TrackPointBean`、
  `VehicleTripVOBean`、`JouDeleteDTO`、`JouMarkDTO`，以及
  `com/zeekrlife/vehicle/view/tripstatistics/` 下的 `TripStatisticsViewModel`
  与 **`TripStatisticsPrivacyPolicyDialog`**（行程统计隐私政策弹窗）。
- ⇒ 行程统计在官方侧是**独立的小程序 + 需同意隐私政策**的功能，
  不是"调一个 REST 接口就有数据"。

#### 资源池文案（`resources.arsc`）里挖到的关键事实

从 `resources.arsc` 解出的中文原文（非猜测）：

| 文案 | 含义 |
|---|---|
| **「行车位置上传功能未开启」** | **真正的开关名是「行车位置上传」，不是"行车日志"** —— 找它 |
| 「行车日志」「行程设置」 | 相关设置项 |
| 「使用车机热点·欢迎您体验行程统计服务」 | 入口引导 |
| 「为了向您提供**行程统计月度报告**、行程统计自定义时间统计服务…」 | 隐私协议开头 |
| 「月度 LCC 行程次数 / 月度 ACC 行程次数 / 月度 LCC 行驶里程数 / 月度 ACC 行驶里程数 / 月度 LCC 使用时长」 | **官方统计口径**（ACC/LCC = 辅助驾驶状态） |
| 「行程统计功能界面包含您的个人信息及隐私，仅对您可见」 | 分享提示 |

⇒ ~~高度怀疑「行车位置上传」没开~~ **已排除**（2026-10-19 用户确认）：
官方 App 里只有一个**「行程统计」开关，且一直开着**，提示语是"关闭后行程数据不会被记录"，
但**依然没有任何逐次行程 / 起终点 / 轨迹**。

**铁证**：同期的真实快照显示，10-16～10-19 之间车辆**实际行驶了 48 km**
（`snapshots` 表，真实 VIN，15 条），而行程接口仍然 `total=0`。

⇒ **定案：官方「行程统计」统计的是月度聚合指标，不产出逐次行程。**
资源文案里写得很清楚（`resources.arsc`）：统计口径是
「月度 LCC 行程次数 / 月度 ACC 行程次数 / 月度 LCC 行驶里程数 / 月度 ACC 行驶里程数 /
月度 LCC 使用时长」—— 这是**月报**，不是行程列表。
`ms-vehicle-trail/trip/listForPage` 对这台车**不会返回数据**，
继续调参没有意义；**应把行程页改造成「能耗」页**（数据来自车况 + 本地快照）。

> 顺带结论：这些文案是 `resources.arsc` 里的，**不是 dex**；用 apktool 能解成
> `strings.xml` 更易读，但**解不出任何接口地址** —— 资源层没有 URL。
- `ms-vehicle-trail` 那 5 条路径确实是官方在用的（SDK 里有 Bean），
  但服务端对这台车返回空 —— 权限有、参数对，**只能是服务端没开/没数据**。

| 试验 | 结果 |
|---|---|
| 原参数 `pageNum` + 无 `lastId` | `total=0` |
| 社区写法 `currentPage` + `lastId`（-1 / 0 / 10^13 / 2^63-1 / 不传） | 全 `total=0` |
| 分页键全不传 / 只传时间 | 全 `total=0` |
| 窗口：10-16 单日 / 10-15~17 / 最近 3 天 / 30 天 / 90 天 | 全 `total=0` |
| 时间单位：毫秒 / 秒 / `yyyyMMdd` | 都 `000000`，都 0（只有 `endTime=0` 会报 `034003`，证明单位是数值比较） |
| 权限包 | **有** `owner-vehicle-trail` + `journey-h5-owner` |
| 轨迹接口带 `tripReportTime` | **`034010 查询数据异常`**（参数合法、无数据） |

⇒ **参数、签名、权限、窗口全部排除。** 剩下唯一自洽的解释是服务端侧的状态：
`journey-statistics-service` 里有个 `POST /api/v2.0/phone/protocolConfirm`，
而 DEX 里确实有一整套「行程统计服务协议」的文案
（`tripStatisticsAgreementTitle` / `...Sure` / `...Cancel`）——
**很可能是"没签协议 ⇒ 服务端不返回行程"**（官方 App 同样看不到按次行程，
与这条吻合）。该接口只接受 POST，**未获用户同意前不要调用**（有协议含义）。

> 补充：`journey-statistics-service` 的 GET 返回
> `52A02 Supported HTTP methods:POST.` —— 服务存在、只收 POST。
> `/v1/evaluation/statistics` 是网关级 404（`00A1` + `bizName: API Gateway`）。

**产品层面的重要事实（用户 2026-10-19 确认）**：官方 App **不显示按次行程**，
也没有起终点，只展示**每月/每天的电耗**；车机与 App 里**都没有行车日志开关**。
所以说"补全官方缺失的行程"这个前提本身不成立 —— 官方在国区没把按次行程作为能力。
界面在有缓存时正常显示历史数据（`api/trips.py` 回源为空时回落到本地库），
不要因为"接口返回空"就以为页面坏了。

### 权限包 `tspPlatform` 取值（枚举实测，非猜测）

`/ms-app-bff/api/1.0/permissions` 的必填参数。2026-10-16 让网关自己回答：

| 取值 | 网关回答 |
|---|---|
| 非数字（`ZEEKR` 等） | `000002 param check failed` —— 参数校验就挂了 |
| `1` / `2` / `3` | `037021 平台类型未定义` |
| `4` | `000000 ok`，但 `data` 为**空数组** |
| `5` / `7` / `8` / `21`…`27` | `000000 ok`，返回该车 **21 项权限**（内容一致） |

⇒ 本项目取 `5`，可用 `.env` 的 `ZEEKR_TSP_PLATFORM` 覆盖。

### 权限包 ≠ 硬件能力（这条边界别踩）

权限包返回的是**服务 / 功能 ID**（`charge-manage` / `vehicle-defence` /
`owner-vehicle-trail` …），**不是**胎压 / 空调 / 车窗这类硬件能力。

因此代码里只允许隐藏**服务类**功能；硬件能力一个都不写进映射表 ——
前端对缺失键返回"照常显示"。拿权限接口去隐藏硬件按钮就是臆测，
宁可多显示一个按了没反应的按钮，也不能把真车有的功能藏起来。
（`tests/test_adapter_shape.py` 有安全断言守着这条边界。）

### 5.1 两把锁（别只开一把）

下发一条车控指令，需要**同时**满足：

| 锁 | 位置 | 默认 |
|---|---|---|
| 客户端总开关 | 网页：设置 → 车辆控制 → 「允许下发控制指令」<br>App：设置 → 车辆控制（同一开关语义，`SettingsStore.commandsEnabled`） | **关** |
| 服务端开关 | `.env` 的 `ALLOW_COMMANDS=true`，改后**必须重启服务** | `false` |

客户端开关关着时，两个客户端的车控按钮一律置灰、标题旁标「已禁用」，并给出一行
「在设置中开启…」的说明 —— 按钮**不隐藏**（隐藏会让人以为功能丢了），
网页与 App 行为已对齐（网页侧用 Node 无头渲染逐条验证过，未入库为回归脚本）。
服务端开关状态在网页「服务连接 → 服务端车控」、App「诊断 → 服务端车控」里都能看到。

> 社区实测发现部分命令存在两套参数（如车窗 `RWS` + 小写 target vs `RWS_2` + 大写 `TARGET`），
> 本项目采用 `RWS` 小写版本，若无效可参考 `borconi/openzeekr` 的 A/B 对照表调整。
