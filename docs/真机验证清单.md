# 真机验证清单

> **背景**：本项目的真实数据链路（极氪国区三网关）尚未在实车上验证过。
> 服务端跑通的是**模拟数据**与**协议实现**，以下项目必须在真机上逐条核对。
>
> 验证顺序按风险从高到低排列，**建议严格按序执行** —— 前面不通过，后面没有意义。

---

## 一、核心门槛：GW3 签名

| 项 | 说明 | 状态 |
|---|---|---|
| 签名头白名单 | 参与签名的头为 `GW3_SIGNED_HEADERS` 中列出的 11 个，**不是**所有 `x-api*` 头 | ⬜ 待验证 |
| 签名版本头 | 需发送 `X-API-SIGNATURE-VERSION: 2.0` | ⬜ 待验证 |
| 待签名串格式 | 头段每行 `name:value\n`（冒号后无空格、行末有换行）；query 段末尾有换行；body 段为 `base64(md5(body))` 且末尾有换行 | ⬜ 待验证 |
| body 字节一致 | 必须用紧凑 JSON 且以 `content=` 发送原文；用 `json=` 会因序列化差异导致验签失败 | ⬜ 待验证 |
| 空值头处理 | `x-vin` 与 `authorization` 为空时**跳过**，其余白名单头即使为空也写入 | ⬜ 待验证 |

**判定方法**：登录后调用 `/api/vehicle/status`。

- 返回 `079025 Signature authentication failed` → 签名串构造有误，对照本节逐项排查
- 返回 `079001 接口未被授权` → 签名已通过，问题在令牌代际或账号权限（见第二节）
- 返回正常数据 → ✅ 通过

**辅助手段**：抓取官方 App 的一次请求，用相同参数（去掉动态字段）本地计算签名，与 App 发送的 `X-SIGNATURE` 比对。这是最直接的验证方式。

## 二、网关与令牌

| 项 | 说明 | 状态 |
|---|---|---|
| 三级登录 | GW1 短信登录 → GW2 换 accessToken → GW3 登录，三级是否都成功 | ⬜ 待验证 |
| 会话持久化 | 重启服务后是否免验证码复用会话 | ⬜ 待验证 |
| `079021` 自愈 | 会话被顶替时能否自动重登并重试一次 | ⬜ 待验证 |
| `079001` 不误重登 | 接口未授权时**不**重新登录（误重登会作废自己正在用的令牌） | ⬜ 待验证 |
| X-VIN 编码 | AES-128-CBC 加密的 VIN 是否被网关接受；若报 `079025 Decrypt X-VIN failed` 说明编码不对 | ⬜ 待验证 |
| X-VIN 令牌 | 若上一条不通，从 App 抓包取 `X-VIN` 头值填入 `ZEEKR_VEHICLE_TOKEN` | ⬜ 待验证 |

## 三、字段映射

网关在不同车型/固件下字段名不一致，需对照实际报文核对。

| 字段 | 期望来源 | 状态 |
|---|---|---|
| 动力电池 SOC | `electricVehicleStatus.chargeLevel`（**不是** `mainBatteryStatus.chargeLevel`，那是 12V 电瓶） | ⬜ 待验证 |
| 续航 | `distanceToEmptyOnBatteryOnly`，应与 App 显示一致 | ⬜ 待验证 |
| 充电功率 | 优先网关直报，否则由电流×电压推算；**量纲需核对**（W 还是 kW） | ⬜ 待验证 |
| GPS 坐标 | 定点整数，量纲为「度 × 3,600,000」；解析器会自动探测四种缩放 | ⬜ 待验证 |
| 锁车状态 | `*LockStatus*` 系列，`0` = 未锁，非 `0` = 已锁 | ⬜ 待验证 |
| 预计充满 | `timeToFullyCharged`，空闲时返回哨兵值 `2047` 应视为未知 | ⬜ 待验证 |
| 车窗状态 | 当前恒为 `None` → 首页「车窗」永远显示「已关」，**属信息不准** | ⬜ 待验证 |
| 车门状态 | 四个车门的字段名与取值语义 | ⬜ 待验证 |

**排查工具**：`GET /api/vehicle/status` 的原始报文可临时加日志输出，或在服务端开 `APP_DEBUG=true` 查看字段溯源。

## 四、车控指令

| 指令 | serviceId | 状态 |
|---|---|---|
| 锁车 | `RDL` | ⬜ 待验证 |
| 解锁 | `RDU` | ⬜ 待验证 |
| 开/关空调 | `ZAF` + `AC` 参数 | ⬜ 待验证 |
| 闪灯 | `RHL` + `rhl=light-flash` | ⬜ 待验证 |
| 鸣笛 | `RHL` + `rhl=light-horn` | ⬜ 待验证 |
| 开始/结束充电 | `RCS` | ⬜ 待验证 |

**注意**：指令返回「已提交」只代表网关收下，**不代表车端已执行**。
验证时必须以**车实际动作**为准，不能只看接口返回。

> 社区实测发现部分命令存在两套参数（如车窗 `RWS` + 小写 target vs `RWS_2` + 大写 `TARGET`），
> 本项目采用 `RWS` 小写版本，若无效可参考 `borconi/openzeekr` 的 A/B 对照表调整。

## 五、安全与合规自查

| 项 | 说明 | 状态 |
|---|---|---|
| 独立子账号 | 是否已新建极氪子账号并共享车辆（**不要用主账号**） | ⬜ 待确认 |
| `ALLOW_COMMANDS` | 默认 `false`；仅在需要车控时开启 | ⬜ 待确认 |
| 会话文件权限 | `data/session.json` 应为 `600` | ⬜ 待确认 |
| 服务端暴露面 | 服务端监听 `0.0.0.0` 且无鉴权，**仅应在可信局域网内运行** | ⬜ 待确认 |
| 密钥保管 | 6 个密钥通过环境变量或 `.env` 注入，**绝不入库** | ⬜ 待确认 |
