## 0. 结论摘要

共 **21 条**（P1 × 6、P2 × 8、P3 × 7），无远程代码执行类漏洞。

**最需要你决定的一条**：服务端目前**没有任何真正的鉴权**（`API_TOKEN` 默认空 = 放行）+ CORS `allow_origins=["*"]`。这意味着——只要你正在跑服务且已登录极氪，你用同一台电脑打开**任意网页**，那个网页的 JS 就能读写 `127.0.0.1:8765` 的全部接口：读车牌/VIN/坐标/账单，删充电记录，在 `ALLOW_COMMANDS=true` 时还能下发车控指令。这是"本地单用户工具"的既有取舍，不是本轮引入的，但仓库是 PUBLIC、文档又鼓励局域网使用，所以列 P1。

其余 P1 是它的分支：`DELETE /api/charges/records` 无鉴权即可清空全部金额证据；写接口的 `_assert_writable()` 只判"是不是模拟模式"，与鉴权无关；`ocr-debug` 无条件返回模型原始输出（可能含手机号/订单号）。

前端 6 条以**并发与状态复位**为主：行程页连切月份会让旧请求覆盖新月份数字；充电页「重试」后骨架不会消失；快速切 tab 会让 `ensureTabData` 把"被跳过的请求"当成"没失败"。没有 XSS 面（`esc()` 覆盖完整）。

## 2. 后端问题

### 2.1 P1 · 无鉴权 + CORS 全开，任意网页可读写本机服务

- 位置：`server/app/main.py:83-89`（CORS）、`server/app/main.py:92-128`（令牌中间件）、`server/app/core/config.py:168`（默认值）
- 证据：`required = config.api_token`，而 `api_token` 默认取 `_env("API_TOKEN")` —— 空串时整个中间件**直接放行**；同时 `allow_origins=["*"]` + `allow_credentials=False`（这个组合语法正确，浏览器允许跨站**读取**响应）。全库 `Depends(` / `Security(` / `HTTPBearer` 命中 **0 处**。
- 后果：已登录用户的浏览器访问任意第三方页面，该页面 JS 可 `fetch('http://127.0.0.1:8765/api/...')` 并读到 JSON（车牌、VIN、坐标、账单），也能 POST。
- 触发条件：服务在跑 + 用户已登录（全局单会话，攻击方无需再登录）+ 访问了带恶意脚本的页面。
- 修复方向：CORS 收敛为显式白名单（`127.0.0.1`/`localhost` + 明确的局域网地址）；首次启动自动生成随机 `API_TOKEN` 写入 `DATA_DIR` 并打印一次；删掉 `?token=` 回退（它还会把令牌写进 access log）。
- **注**：iOS 端若确实直连 8765，改白名单会动到联调方式 —— 需要与"iOS 怎么连"一起决定，不能简单 `*` → `localhost`。

### 2.2 P1 · `DELETE /api/charges/records` 无鉴权、无守卫，一条请求清空全部金额

- 位置：`server/app/api/charges.py:804-810` → `server/app/core/store.py:287-291`（`DELETE FROM charge_records`）
- 后果：金额是靠 OCR/手工一条条补的，清空后**不可恢复**（`charge_records` 没有软删除）。
- 与同类对比：所有写接口都调 `_assert_writable()`，唯独这个没调。
- 修复方向：加鉴权 + 一次性确认票据 + 先备份再清（或改软删除）。

### 2.3 P1 · `_assert_writable()` 名实不符，写接口实际无守卫

- 位置：`server/app/api/charges.py:718-728`；调用点 `:628`（commit）、`:639`（manual）、`:687/:704`（link/unlink）、`:764`（import）
- 证据：函数体只有 `if is_mock(): raise HTTPException(503, ...)` —— 它防的是"模拟模式下别写假金额"，与身份、来源、权限**全部无关**。
- 后果：任意调用方（包括 §2.1 里的网页）可伪造/篡改账本。
- 修复方向：拆成 `assert_not_mock()`（保留原用途）与 `require_write()`（新增鉴权）两个函数。

### 2.4 P1 · `POST /api/charges/receipts/ocr-debug` 无条件返回模型原始输出

- 位置：`server/app/api/charges.py:613-626`
- 证据：`_read_and_ocr(file, include_raw=True)` 直接返回 `raw`（模型原文）与 `parsedRows`（未清洗字段）。函数自己的 docstring 写着"⚠️ 只许本机调试：这两样可能含 prompt 没拦住的 VIN / 手机号 / 完整订单号"。
- 后果：配合 §2.1，任意网页可反复调用，既拿到本不该出的原文，也白烧第三方视觉模型额度。
- 修复方向：默认关闭，仅 `config.debug` 且来源是 127.0.0.1 时允许；`raw` 落盘前先脱敏。

### 2.5 P1 · 车控指令只靠一个环境变量把门

- 位置：`server/app/api/vehicle.py:96-110`、`server/app/core/config.py:159`
- 证据：唯一授权判断是 `config.allow_commands`（默认 False），请求体里的 `vin` 与 `command` 均不校验白名单（白名单只存在于 `adapters/mock_client.py:387` 的 `COMMAND_MAP`）。
- 后果：开关一旦打开（文档鼓励打开），§2.1 的网页即可对任意 vin 下发鸣笛/空调/解锁。
- 触发条件：`ALLOW_COMMANDS=true`（当前默认 False，所以现在不可复现，但它是"改一个环境变量就失守"的形态）。
- 修复方向：车控单独加来源校验 + 一次性确认票据 + 操作审计日志；指令名按 `COMMAND_MAP` 校验，未知指令 400。

### 2.6 P2 · 金额补录提交时，不存在的充电流水会 500 并中断整批

- 位置：`server/app/api/charges.py:496-498` → `server/app/core/store.py:589-594`
- 链路：`link_payment` 查不到流水时 `raise KeyError`，`_persist_payments` 没有 `except` → 异常冒成 500。
- 后果：请求里前几行 `save_payments` 已提交、状态停在 `pending`，后面一行都没写；前端只看到"提交失败"，重试会重复写入已成功那几行。
- 触发条件：OCR 结果在弹层停留期间，那笔流水被另一次同步/清理删掉，用户再点「确认补录」。
- 对照：同文件 `POST /api/charges/payments/{id}/link`（`:697-700`）有 `try/except KeyError → 404`。
- 修复方向：逐行 `try/except KeyError` 收集未绑定项，其余照常写入，回报里带上 `unbound` 列表。

### 2.7 P2 · `POST /api/charges/sync` 与 `POST /api/auth/logout` 无鉴权

- 位置：`server/app/api/charges.py:253`、`server/app/api/auth.py:108-117`
- 后果：前者只有 10 秒全局节流，任意网页可每 10 秒催一次上游同步 → 极氪网关风控/账号异常；后者是全局单会话，任意网页可把用户踢下线。
- 与 §2.1 同源：加鉴权即一并解决。

### 2.8 P3 · 逐日电耗把"缺失"解析成 0

- 位置：`server/app/adapters/live_client.py:1748-1752`（月度 `num`）、`:1859` 附近（逐日同一实现）
- 后果：上游某天只给 `null` 时该天 `dynamicKwh`/`staticKwh` 变真 0，页面显示 `0` 而非 `--`；而 `store.py` 的 `dynamic_kwh` 刻意允许 NULL 并把 NULL 与 0 分开存 —— 这一层解析又把区分抹掉了。
- 修复方向：`num()` 返回 `float | None`，调用处显式决定落 0 还是保留 None。

### 2.9 P3 · `/api/vehicle/snapshots` 的 `limit` 无约束

- 位置：`server/app/api/vehicle.py:166`
- 后果：`limit=-1` 时 SQLite 的 `LIMIT -1` 表示**不限条数**，一次返回全部历史快照（按 60 秒一条累积）。
- 修复方向：`Query(200, ge=1, le=1000)`。

### 2.10 P3 · `trips.py` 的 `detail=str(exc)` 是回归口子

- 位置：`server/app/api/trips.py:285`
- 现状：当前 `exc` 是本地 `ValueError("days 取值范围为 1–60")`，不泄密。
- 风险：这正是 `api/__init__.py:16-37` 注释里点名要消灭的模式，将来上游异常穿到这里就会把网关报文（可能含令牌）透给客户端。
- 修复方向：改成 `fail("补齐日电耗失败，请查看服务端日志", exc)`。

### 2.11 P3 · `GW1_CA_SECRET` 硬编码随公开仓库发布

- 位置：`server/app/adapters/zeekr_signing.py:149-155`
- 现状：`os.environ.get("ZEEKR_CA_SECRET") or "MIGfMA0GCSqGSIb3..."` —— 有回退常量，注释自述"App 内置常量"。
- 影响：不是用户 PII，但是逆向所得的第三方网关密钥，仓库 PUBLIC ⇒ 可被他人拿去滥用极氪网关，也可能因此让你自己的账号被风控。
- 修复方向：移除硬编码，只读 env，README 说明需自行获取。

### 3.1 ✅ P2 · 行程页连切月份，先发的请求后到会覆盖新月份数据

- 位置：`preview/index-v2.html:6571-6601`（`loadTrips`）、`:7143`（月份回调）
- 证据：回调 `onPick: (v) => { state.yearMonth = v; loadTrips().then(render); }`，而 `loadTrips` 在 `await` 后**直接赋值** `state.energy` / `state.energyWindow`，无"响应回来时月份是否还是发起时那个"的比对。
- 后果：快速连点两个月（10 月 → 9 月），9 月先回、10 月后回 → 标题「2026年9月」+ 10 月数字；不会自愈，要再切一次。
- 对照：`loadChargeSessions`（`:6655-6665`）就是 `const want = state.chargeMonth` + `if (state.chargeMonth !== want) return false`。
- 修复方向：照抄充电页写法。

### 3.2 ✅ P2 · 充电页「重试」后停在骨架不消失

- 位置：`preview/index-v2.html:6725-6726`（置 `chargeLoading=true` + `render()`）、`:6751-6753`（finally 只清标志不 render）、`:7159-7163`（`#chargeRetryBtn` 调用点无 `.then(render)`）
- 后果：`renderCharges` 的骨架条件是 `!c && chargeLoading`（`:4606-4612`），标志清了但没人重新渲染 → 页面停在「加载中」，直到下一次轮询（60s/300s）或切 tab 兜到。
- 修复方向：`finally` 里 `render()` 一次，或调用点改 `loadCharges().finally(render)`。

### 3.3 ✅ P2 · `ensureTabData` 把"被跳过的请求"当成"没失败"，可能误判 `mode='live'`

- 位置：`preview/index-v2.html:6991-7012`、`:7016-7023`
- 证据：`if (loadingKeys.has(key)) return;`（`:6993`）跳过的 key 既不进 `loadedKeys` 也不进 `failed`；`finally`（`:7006-7012`）**无条件**清 `loading/statusLoading/chargeLoading/energyLoading`；随后 `:7016-7023` 按 `failed` 判可达性。
- 后果：快速切 tab 或 `visibilitychange`（`:7671-7673`）在请求在飞时触发 → 后端已挂仍可能判 `mode='live'`，骨架提前消失后又跳变。
- 修复方向：清理只放进真正发起请求的分支；或把 skipped 计入"未确认"，不参与 live 判定。

### 3.4 ✅ P2 · 快速连切月份会误弹「读取该月流水失败」

- 位置：`preview/index-v2.html:6662` + `:7176-7179`
- 证据：`if (state.chargeMonth !== want) return false;` —— 被作废的那次返回 `false`；而回调 `if (ok === false) toast('读取该月流水失败')` 把它当失败。
- 修复方向：过期返回用第三个值（`null`/`'stale'`）区分，回调不弹。

### 3.5 ✅ P3 · 退出登录未复位月份/区间/推荐位等用户态

### 3.7 ✅ P1 · 电池 `soc` 为 `null` 时首卡谎报 0%

### 3.8 ✅ P2 · `records` 缺失时整个充电页停在上一帧、无任何提示
